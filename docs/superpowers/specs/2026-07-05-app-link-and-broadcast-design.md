# Дизайн: кнопка застосунку Nutriday + механізм розсилки

- **Дата:** 2026-07-05
- **Статус:** Затверджено + деталізовано (grilling); готово до планування реалізації
- **Стек:** NestJS · node-telegram-bot-api · MongoDB/Mongoose · OpenAI

## 1. Контекст

Існує повноцінний веб-застосунок Nutriday (`nutriday.com.ua`) з розширеним функціоналом:
меню на тиждень, заміна окремої страви, список покупок, підрахунок БЖВ. Потрібно:

1. Додати в Telegram-бот кнопку-посилання на застосунок.
2. Побудувати багаторазовий механізм розсилки повідомлень користувачам бота, щоб
   повідомити про новий сервіс і його розширений функціонал.

У системі ~2000 користувачів, більшість неактивні. Розсилка — це насамперед
кампанія, тож таргетинг і обробка заблокованих критичні.

## 2. Цілі

- Inline URL-кнопка на застосунок у кількох точках бота.
- Багаторазова адмін-команда `/broadcast` (текст або фото + кнопка застосунку).
- Тротлінг, обробка помилок Telegram, позначка заблокованих користувачів, звіт адміну.
- Розсилка лише активним користувачам.

## 3. Non-goals (YAGNI)

- Персистентна/відновлювана черга розсилки (fire-and-forget у пам'яті процесу).
- Лог доставки по кожному користувачу.
- Планувальник розсилок, A/B, аналітика поза UTM.
- Тригер розсилки через REST API / адмін-панель.
- Відео/документи в розсилці (лише текст або фото).

## 4. Ключові рішення

| Питання | Рішення |
|---|---|
| Тип кнопки | Звичайна inline URL-кнопка (не web_app) |
| Місця кнопки | Reply-клавіатура, після видачі меню, `/start` + `ℹ️ Допомога` |
| Запуск розсилки | Адмін-команда `/broadcast` (обмежена `ADMIN_CHAT_ID`) |
| Вміст розсилки | Багаторазовий: текст (≤4096) або фото + підпис (≤1024); кнопка застосунку завжди |
| Обробка доставки | Тротлінг ~25/с, обробка 429, позначка заблокованих у БД, фінальний звіт |
| Аудиторія | Лише активні: `amountMenu > 0` та `isBlocked !== true` |
| Формат тексту | Простий текст (без Markdown) |
| Ідентичність адміна | `ADMIN_CHAT_ID` у `.env` через `ConfigService`; фідбек мігрує на нього ж |
| Стан адмін-діалогу | Інкапсульований у `BroadcastService`, делегація з головних обробників |
| Виконання | Фон, fire-and-forget, ~25/с (пауза ~40мс на повідомлення) |
| Звітування | Ack на старті + фінальний звіт (без проміжних) |
| Позначка заблокованих | Помилки 403 та 400 "chat not found" → `isBlocked`; 429 → повтор; інше → transient |
| Скидання `isBlocked` | На будь-якому вхідному апдейті (guarded update) |
| Прев'ю | Два повідомлення: реальна копія + окремий контроль підтвердження |
| Гарди діалогу | Тайм-аут чернетки ~10хв, захист від подвійного тапу, заборона паралельного run |
| Тести | Фокусні unit-тести `BroadcastService` + `appButton`; полагодити зламаний spec |

## 5. Фіча A — Кнопка застосунку

### 5.1 Спільний хелпер
Новий `src/utils/appButton.ts` повертає inline-клавіатуру з однією URL-кнопкою
`🥗 Відкрити Nutriday`. Хелпер параметризований варіантом URL:
`appButton('cta' | 'invite')` — точки в боті (меню, start, help, reply-клавіатура)
використовують `cta`; розсилка використовує `invite`.

### 5.2 URL-и (в config/constants)
- **CTA-кнопка:** `https://nutriday.com.ua/?utm_source=telegram&utm_medium=referral&utm_campaign=miniapp&utm_content=cta-button`
- **Запрошення (розсилка):** `https://nutriday.com.ua/?utm_source=telegram&utm_medium=referral&utm_campaign=miniapp`

### 5.3 Точки показу
- **Reply-клавіатура:** до `mainKeyboard` додається другий ряд `[🥗 Застосунок]`.
  Reply-кнопка не тримає URL, тож її натискання ловиться в обробнику `message`
  (точний збіг тексту, поряд із `📋 Меню`/`ℹ️ Допомога`) → бот надсилає коротке
  промо-повідомлення з inline URL-кнопкою (`cta`).
- **Після `/menu`:** inline-кнопка (`cta`) прикріплюється до відредагованого
  повідомлення з меню (`reply_markup` в `editMessageText`) — **щоразу**, з підводкою
  про розширений функціонал.
- **`/start` і `ℹ️ Допомога`:** inline URL-кнопка (`cta`) окремим коротким
  повідомленням (reply-клавіатуру й inline-кнопку не можна поєднати в одному
  повідомленні).

## 6. Фіча B — Механізм розсилки

### 6.1 Зміна моделі даних (`User` schema)
- `isBlocked: boolean` (default `false`) — `true`, коли надсилання повертає
  403 або 400 "chat not found".
- `blockedAt?: Date` — час позначки (опційно).
- **Скидання:** у головних `message`/`callback_query` обробниках виконується
  guarded-update `updateOne({ chatId, isBlocked: true }, { $set: { isBlocked: false } })`
  — пише лише якщо користувач наразі позначений; майже нульова вартість.

### 6.2 Визначення аудиторії
«Активний» = `amountMenu > 0` **та** `isBlocked !== true`. Методи в `UserService`:
`findActiveForBroadcast()` та `countActiveForBroadcast()`.

### 6.3 `BroadcastService` (модуль telegram)
Новий сервіс, що інкапсулює весь потік. Внутрішній стан чернетки (in-memory Map,
фактично один адмін): `idle | awaiting_content | awaiting_confirm | sending`.

Потік:
1. Адмін → `/broadcast`. Дозволено лише якщо `chatId === ADMIN_CHAT_ID`; команда
   **не** додається в `setMyCommands`. Якщо вже `sending` — відхилити
   («розсилка вже виконується»); якщо є чернетка — перезапустити її.
2. **Захоплення контенту** (`awaiting_content`): приймає одне текстове повідомлення
   (≤4096) **або** одне фото з підписом (≤1024). Інші типи (відео/файл/альбом) або
   перевищення довжини → пояснення й повторний запит, лишаючись у стані.
3. **Прев'ю** (`awaiting_confirm`): два повідомлення адміну —
   (a) точна копія розсилки (текст/фото + кнопка `invite`);
   (b) контроль: «Надіслати N активним користувачам?» з inline
   `✅ Підтвердити` / `❌ Скасувати`. `N = countActiveForBroadcast()`.
   Якщо `N === 0` — повідомити й не запускати.
4. **Підтвердження**: тап `Підтвердити` → стан `sending` (ігнорує повторні тапи),
   ack «Розсилку почато (N)», `runBroadcast()` запускається у фоні (не awaited).
5. **`runBroadcast()`**: `findActiveForBroadcast()`, послідовна ітерація з паузою
   ~40мс (≈25/с), `sendMessage`/`sendPhoto` + кнопка `invite`. Обробка помилок:
   - `403` / `400 "chat not found"` → `isBlocked = true`, лічильник «заблоковано».
   - `429` → чекати `error.response.body.parameters.retry_after`, повторити цього юзера.
   - інше (5xx/мережа) → лічильник «помилка», лог; **не** позначати.
6. **Фінальний звіт** адміну: всього / надіслано / заблоковано / помилок / тривалість.

Гарди:
- Тайм-аут чернетки ~10хв простою → авто-скасування.
- Заборона старту нового `run`, поки триває поточний.
- Якщо адмін замість контенту вводить команду → чернетка скасовується.

### 6.4 Інтеграція з `telegram.service.ts`
Делегація з **єдиних** головних обробників (без нових глобальних `bot.on`, на
відміну від `SurveyService`):
- `onText(/\/broadcast/)` → `broadcastService.start(chatId)`.
- На початку `message`-обробника: `if (broadcastService.isAwaitingContent(chatId))
  return broadcastService.handleContent(bot, msg)` — передається весь `msg`
  (сервіс сам читає `photo`/`text`).
- `callback_query` роутить `broadcast:confirm` / `broadcast:cancel`.
- Guarded-скидання `isBlocked` (див. 6.1) на вході в `message` та `callback_query`.

### 6.5 Конфіг / константи
- `ADMIN_CHAT_ID` у `.env`, через `ConfigService`. Наявний фідбек-обробник
  ([telegram.service.ts:205](../../../src/telegram/telegram.service.ts)) мігрує на
  те саме джерело (одна крапка правди).
- URL-и застосунку та константа швидкості тротлінгу — у config/constants.

## 7. Крайові випадки

- **Фото:** беремо найбільший `file_id` з `msg.photo`; `sendPhoto` з caption + кнопкою.
- **Довгий підпис:** якщо фото+підпис > 1024 → відхилити з поясненням (не різати).
- **Parse mode:** за замовчуванням простий текст (без `parse_mode`).
- **Event loop:** розсилка async з паузами — не блокує обслуговування інших юзерів.
- **Порожня аудиторія:** `N === 0` → повідомити адміну, не запускати.
- **Перезапуск процесу під час розсилки:** не відновлюється (свідомий non-goal).
- **Адмін в аудиторії:** якщо в адміна `amountMenu > 0`, він теж отримає розсилку
  (нешкідливо, слугує підтвердженням доставки).

## 8. Тестування

Jest (ts-jest, `*.spec.ts`, `rootDir: src`).

- `BroadcastService` (мок `bot` і `UserService`):
  - класифікація помилок: `403`/`400 chat not found` → позначка; `429` → повтор
    з `retry_after`; `5xx` → transient без позначки;
  - підрахунок фінального звіту (надіслано/заблоковано/помилок);
  - валідація контенту (довжина, тип);
  - фільтр аудиторії (`findActiveForBroadcast`).
- `appButton` — коректний URL для `cta`/`invite` і структура клавіатури.
- Полагодити наявний `telegram.service.spec.ts` (мокнути залежності або спростити),
  щоб `npm test` був зелений.
